# Changelog

## 0.5.0 (2026-09-08)

2026-07-27 to 2026-09-08. Covers everything merged into `main` since `v0.4.1` (commit a714e48a): the last three in the range are #288, #292, and #293.

This is a minor version bump rather than a patch because it carries new syscalls (`sys.ledger.list`, `sys.target.*`, `ai.models`, `contact.*`, `r12y.*`, `conversation.*`), Kernel schema migrations 15 through 39, a wire protocol cut-over to version 4, and new host (daemon) behaviour such as self-update and resource references. Existing installations upgrade in place; the notes in the first section say what needs attention.

### Breaking changes and upgrade notes

- Every client must be on this release: the wire protocol moved from version 2 to version 4, and the gateway refuses older handshakes. Version 3 modelled browsers, native clients, machines, and adapters as protocol peers with separate principal, grant, transport, and provenance axes, and added generated validation of the wire frames (#238).
- Protocol version 4 renamed devices to targets (`sys.device.*` became `sys.target.*`, `/sys/targets` in the filesystem), renamed token kinds (`node` to `machine`, `user` to `human`) and dropped token roles, unified request, response, and signal envelopes around `call`, `data`, and `signal`, added credit-based body flow control (4 MiB windows, `WINDOW` frames, per-side stream id parity), and deleted the legacy connection identity (#280).
- A client that stayed connected through the deploy on the old protocol is closed and sent back through `sys.connect`, where it receives the structured upgrade error instead of silently resuming (#280).
- Kernel schema migrations 15 through 39 run on first start: 15 removes the package runtime (#221); 16 and 17 rework system context (#223); 18 removes the Kernel conversation registry (#228); 19 removes notifications (#235); 20 to 32 add mailboxes, outbound mail, the personal controller slot, surface route modes, private adapter destinations, conversations, durable tasks, the Ship rename, responsibilities and their source policies, and adapter run-route fencing (#238); 33 and 34 add federation and process approval routes (#243); 35 adds adapter lifecycle ids (#250); 36 supervises delegated IPC (inter-process communication) calls (#262); 37 and 38 cut over to protocol 4 and rename the devices tables to targets (#280); 39 adds the ledger (#289).
- Process schema migrations 7 through 13 and the new Conversation store (migrations 1 through 3) also run on upgrade; adapters gain their own SQLite migrations (`adapter_hil` for Telegram and Slack, and four for managed email) (#223, #228, #238, #243, #252, #265).
- Machine daemons (`gsvd`) must be updated before they can reconnect, because of the protocol cut-over (#280). Once on this release they update themselves when the gateway moves ahead (#284). Older daemons also cannot serve immutable file references for reads (#238), list a symlinked folder as a folder (#288), or answer the new `reference` read representation, which the Send tool needs when attaching a document from a machine; until a daemon updates, only images can be attached from it (#293). Content types are now named once, the same way for every daemon operation, so a reference made by a read verifies against the transfer that retains it (#293).
- Adapter workers must be deployed together with the gateway: the legacy adapter RPC (remote procedure call) path, the adapter-owned delivery queue, its staging and chunk storage, and the `adapter.delivery.claim` and `adapter.delivery.report` calls are gone; delivery is one correlated `adapter.send` request per destination (#265).
- Removed end to end: the package runtime and its syscalls, CLI (command-line interface) commands, assembler worker, and SDK (software development kit) bridge (#221); the notification syscalls, panel, and service-worker sound (#235); the `gsv deploy` and `gsv infra` commands, replaced by the public Alchemy stack or Managed GSV (#238); the `proc.media.write`, `proc.media.read`, and `proc.media.delete` calls, replaced by resource references (#238).
- Process-source R2 overlays under `/src/repos` are ignored rather than migrated: repositories are now a single ripgit-backed state, and filesystem writes commit directly to the configured ref (#254).
- `proc delegate --timeout` no longer kills the child; it is a compatibility alias for `--check-after`, which sets a 10-minute supervision cadence. Already scheduled legacy timeouts are upgraded into checkpoints (#262).
- The model's primary path for replying is now the `Send` tool, not the `message send` heredoc in the Shell. The shipped prompts, the Shell's run-control instruction, and the correction text all point at Send; the shell forms remain documented as the same actions (#291, #292).
- The fixed model-facing surface in `AGENTS.md` is eight tools: Read, Write, Edit, Delete, Search, Shell, CodeMode, and Send. Send is the only tool that is not a capability (#291).
- Model settings changed shape: one human-owned ordered stack of complete model entries replaces copied provider field bags. Legacy settings stay readable, but setup and console writes use the stack, and the static default `config/ai/models` is gone; a managed installation with no explicit stack resolves to GSV Included with no migration (#269, #281).
- The built-in Workers AI default moved from GLM-5.2 to GLM-5.3-Flash, and every text-generation default and fallback rose from 8k to 32k output tokens (#257, #259).
- Automatic compaction is now pressure based: it triggers at 90% of the usable input budget and retains about 40%, instead of keeping a fixed number of messages (#260, #269).
- New host installs go to `~/.gsv/bin` on Linux and macOS (Windows already used `%LOCALAPPDATA%\Programs\gsv\bin`) and need no `sudo`; the installer adds one guarded line to the shell profile unless `GSV_NO_MODIFY_PATH=1`. Existing installs stay where they are and the installer prints the migration command if that directory is not user-writable (#284).
- For contributors, the source layout moved: the gateway, adapters, and ripgit now live under `workers/`, and all Rust host code under one `host/` workspace. Worker names, bindings, and Durable Object identities are unchanged (#238, #267).

### For people using GSV

- Your personal intelligence is now one canonical conversation called Ship, reached from every surface, with one replaceable Kernel-marked process behind it. Private adapter messages route to Ship by default (#238).
- Opening a separate piece of work no longer replaces Ship: Work Sessions have visible identity and a reliable Back-to-Ship path on Web and Desktop (#238).
- Replies are explicit: a message is committed with the `Send` tool (or `message send`) without ending the run, `yield` ends a human-facing run, and a final reply composes both. Each send gets its own durable identity, so several progress messages from one run each deliver exactly once (#238, #291).
- The model has a `Send` tool with `text` and `yield`. Text alone sends and continues; text with `yield: true` sends and finishes; `yield: true` alone finishes quietly, and staged media on a yield-only Send goes out as the final message (#291).
- When a turn ends in text without sending, the correction names Send and comes back for up to three rounds instead of one, with the tool set unchanged from turn to turn so the cached prompt prefix survives (#291, #292).
- If correction still fails, you receive "I wrote a reply but did not send it. Ask me again." instead of silence (#291).
- A bare yield now ends the run whatever the turn narrated, so the Ship no longer sends a filler line to be allowed to close quietly after a background wake. This reverses the guard added in #282 (#292).
- Replying in the current conversation is transport-neutral, `--to here` is explicit, and a terminal delivery notice survives the run's teardown when a reply could not be delivered (#269).
- Delegated work is supervised rather than killed on a timer: Ship is told the child is still running at each `--check-after` checkpoint, and results route back to the caller with cancellation and late-result fencing (#238, #262).
- Spawned tasks get a descriptive title automatically, generated in the background from the first message; explicit labels opt out (#227).
- You can branch a process from a message, a run, or a compacted segment; the branch is labelled "Branch of <source>", and each process owns its single history (#228).
- Standing context is layered from `context.d` folders: `config/ai/context.d` for the installation, your home `context.d` for facts and instructions that shape every agent you own (the conventional file is `10-personal.md`), and the agent's own `context.d` for its role, voice, and program state. The default seeded context was simplified, an image-reading skill was added, and bundled skills are reconciled on upgrade without overwriting your edits (#221, #223, #238).
- Ship captures useful person and relationship context proactively into memory, and a gzip Process-archive recovery path is documented (#254).
- Remaining context tokens are shown in clients, and Ship receives one durable "context runway" event per context epoch before compaction, so it can tidy up before the hard safety net; a provider-confirmed overflow compacts once and retries the same model instead of falling through the fallback chain (#240, #252).
- Obligations that outlive a turn live in a Kernel-owned responsibility ledger (`r12y`): user work, schedules, delegation, mail, onboarding, and maintenance, each with state, timing, and revision history. The old generated `00-boot.md` onboarding became a waiting responsibility. The Web Responsibilities view shows required and configurable sources and next-check timing (#238).
- Lifecycle responsibilities are created when a machine first registers, when a contact pairing is made (a learning responsibility on both sides), and when an adapter loses authentication; the last resolves itself after recovery (#250).
- Telegram: a platform-owned shared bot with signed, one-time, human-confirmed pairing into your installation; text, images, files, audio, and voice both ways; native approval buttons for tool approvals (#238, #265, direct fix 2dd35d00 for approval updates).
- WhatsApp: a new adapter, deployable on the free Workers plan, with make-before-break credential refresh and a resident session kept alive by a 30-second alarm so messages stop arriving minutes late (#236, #237, #239).
- Slack: a new adapter, standalone and managed, with per-person pairing, channel and thread routing, file transfers, and approval buttons. A managed workspace is also a target: a `slack` command environment for conversations, threads, messages, reactions, and users, reading with your OAuth visibility and writing as the installed app (#255, #265).
- Discord is described by the same data-driven adapter catalog and receives replies, with approval prompts as correlated text, through the same protocol path as the others (#238, #265).
- Mail: managed inbound and outbound email with mailbox state, replay-safe summaries, and a bounded untrusted summary delivered to Ship in a notify-only run that cannot execute forged tools; outbound mail has sender and destination restrictions, budgets, retries, and status (#238). Inbound bodies now relay as byte streams (#247), and `mail address`, `list`, `search`, and `show` let a received message be read rather than reconstructed (#280).
- Contacts: two GSVs can federate over a signed, one-shot transport with durable invites, delivery, replay protection, and requests. Ship configures it through `contact` commands, contact conversations outlive processes, and a Contacts workspace appears in the Web app (#243). An incoming contact's requests consult you before Ship replies or acts unless standing permission applies (#254), and media from a contact is admitted through the handler's subprocesses (#280).
- Files and media are represented once as immutable resource references; bytes move only when something resolves them, and each history entry keeps the exact revision it saw even when the file changed later (#238).
- Paths can name their place: `target:path`, or `[target]:path` when the target id itself contains a colon, works in `cp` and in `Send { attach }`, so a file on your laptop can be sent without copying it to the cloud home first (#280, #293).
- A symlinked folder on a machine lists as a folder and opens, instead of showing as a file that "would not open" (#288).
- Copying more than about 512 KB between targets no longer fails: frames are coalesced and receivers bound by the byte window (#280, closes #273). `split` works on the cloud filesystem and a native `dd` covers byte-range slicing (#280).
- Reads are bounded so one large file cannot exhaust the model's context: the agent Read defaults to 2,000 lines and caps text at 64 KiB with a continuation offset (#238). Machine searches are bounded by file count, per-file bytes, total bytes, and result count, and skip symlinks, binaries, and oversized files (#249).
- Offline machines still appear in the agent's `targets list`, labelled offline, so Ship can tell you a machine is asleep rather than unknown (#225).
- The installation keeps a ledger of every syscall: who, where, the call, the whole input as sent (cut at 16 KB with the cut marked), outcome, duration, and tokens and cost for model calls. The active window holds 5,000 lines in the Kernel; older lines rotate into immutable R2 (Cloudflare object storage) segments of up to 2,000 lines or 4 MB, and everything is deleted after 90 days (#289).
- Web: the CREW page was rebuilt on the shared list template with an in-body defaults editor, so model, permissions, and global instructions save together (#219).
- Web: the overview uses the new data cards and dialogs, the rail starts collapsed, the header shows the app version, closing a surface returns to where it was opened, and the notifications bell is gone from the status bar (#230, #235).
- Web: usernames are lowercased as you type with per-field validation, the add-model screen shows "make default" as a checkbox, and duplicate model profiles are rejected (#226, #229).
- Web: the chat surface streams Markdown and media, shows message attachments and remaining context, and exposes history segments with compaction controls (#238, #252).
- Web: the models page shows the layered stack, with Included and shared entries read-only after your own and a "set as primary" action on any entry (#269, #281).

### For people running GSV on their machines

- An outdated `gsvd` brings itself up to the release the gateway runs: a protocol rejection or a newer stable release on connect triggers a download of the installer, pinned to that release, run detached from the daemon's own service (a transient `systemd-run --user` unit, a new session on macOS, a detached process group on Windows) so it can stop, swap, restart, health-check, and roll back the daemon (#284).
- Self-update guardrails: at most one attempt per hour, only releases the gateway named, only under a service manager, never while the machine is busy, never into a non-writable directory or the macOS app bundle, a stable daemon never follows a `dev` gateway, and work-creating requests are refused with a retryable 503 while installing. `device.auto_update` in the host config turns it off and is re-read at every handshake; decisions show in `gsv daemon diagnostics` and `~/.gsv/logs/auto-update.log` (#284).
- The CLI is not auto-updated; it prints one line when the gateway is newer. Desktop is untouched, and a daemon that Desktop enrolled inside its macOS bundle is left to Desktop (#284).
- The installer treats the CLI, daemon, Desktop, and the transcription and vision helpers as one versioned set, verified against the release's `checksums.txt`, swapped transactionally, and rolled back together if the health check fails; a pinned `GSV_VERSION` install runs that release's own installer (#251).
- A pinned `GSV_VERSION=dev` install records `release.channel = "dev"` in the host config so the daemon classifies itself as dev; `GSV_CHANNEL=dev` selects the moving channel (#284).
- Existing service definitions that invoke `gsv device run` are migrated to `gsvd --foreground` without changing the service identity; `gsv daemon install|start|restart|stop|uninstall` controls the per-user service and `gsv daemon status|reload|reconnect|diagnostics` talks to the running daemon over a bounded local control protocol (#238, #284).
- Directory listings on a machine run on the blocking thread pool so a large folder does not stall the daemon's async runtime, and a link to a directory lists as a directory (a broken link still lists as a file) (#288).
- The daemon's Read returns a revision-bound reference for images instead of raw bytes when asked for the resource representation (#238); a separate `reference` representation does so for any file, with `kind: "file"` for content that is neither text nor an image, without reading the bytes, while ordinary reads are unchanged (#293).
- Machine shell responses conform exactly to the public `shell.exec` contract, and the browser extension releases its command queue when a command ignores cancellation (#249).
- A burst of already-buffered binary frames no longer cancels an in-flight request: consumers get a cooperative scheduling turn, while a genuinely stalled receiver still fails fast (#264).
- Desktop is a new native application built on GPUI (a Rust user-interface framework): it enrols and names the machine on first run, starts, stops, and reconnects `gsvd` over local IPC, has tray controls for gateway, machine, voice, and gestures, and renders streamed activity, messages, media, and approvals (#238).
- Voice and gestures run natively: a Rust hand-tracking pipeline with pinned TFLite models replaces the Java and MediaPipe runtime, with gesture arming, voice control, dictation correction, held scrolling, and microphone selection (`gsv desktop microphone list|use|default`) (#238).
- The `gsv-vision` helper is published for Linux x64 and ARM64 and macOS Intel and Apple Silicon and installed with its verified model license and provenance files (#251). The Linux x64 Desktop link failure from a BLAS (Basic Linear Algebra Subprograms) linker argument is fixed by upgrading the transcription dependency (#246).
- The `gsv` CLI consumes the same structured approval signal as Web and Desktop (#265), and the CLI's `gsv token create` flags changed with the removal of token roles (#280).

### For builders

- `sys.ledger.list` reads the ledger newest first, paged by cursor, filtered by `pid`, `target`, `callPrefix`, `since`, and `until` (limit 200), with the visibility rule `proc.list` uses; the coalesced `ledger.appended` signal carries the newest sequence so a surface can tail without polling. Reads are recorded but do not signal (#289).
- `sys.target.list`, `get`, `update`, and `delete` replace the `sys.device.*` calls; capability rows are rewritten by migration 37, and registered targets appear under `/sys/targets` (#280).
- `ai.models` returns the effective ordered model stack with each entry's `source` layer and `hasCredential`, never the credential; it is granted to users by default and seeded on every bootstrap (#281).
- Text models resolve from three layers, each extending the ones beneath: `users/{uid}/ai/models`, `config/ai/models`, and an implicit deployment base (GSV Included on managed installs, the Workers AI pair on self-hosted). Entries dedupe by id or by provider, model, endpoint, style, and transport; `users/{uid}/ai/preferred_model` promotes any entry to the front (#281).
- `fs.read` accepts `representation: "content" | "resource"`; resource mode returns a `FileResourceReference` (target, path, revision, content type, size, optional expiry) with no body for images, and messages and tool results carry a typed `ResourceBlock` instead of inline bytes. Base64 is confined to legacy input and provider APIs that require it (#238). A third value, `reference`, answers any file with its reference alone, on the cloud driver, the daemon, and the browser extension, which gains content-hash revisions for its transfers (#293).
- The `Send` tool (`text`, `yield`, `attach`) is classified as run control by the process runtime and shares handlers with the `message send` and `yield` commands; it is recognised only where it was offered, never in a bounded IPC run, and its results are recorded under its own name (#291, #293). Attachment reads obey the person's tool approval rules; a read the person approved earlier in the run, once or for good, may be attached without asking again (#293).
- Delivery to adapters is one `adapter.send` request per exact destination with a stable `deliveryId`; the Kernel owns retry, live-route rechecks, and cleanup, the adapter owns rendering, idempotency, and body consumption. Routed HIL (human-in-the-loop) sends carry the structured `ProcHilRequest`, and native callbacks come back as an ordinary `proc.hil` request through a Kernel-derived linked human peer (#265).
- `shell.exec` requests may carry target routing metadata (#261); `proc.delegate` gains `--check-after` and a durable supervised-call flag, while `proc.call` keeps strict deadlines (#262); `proc.fork` branches from a `throughMessageId`, `throughRunId`, or `segmentId` (#228).
- New syscall families: `conversation.*` for canonical messages (#238), `r12y.*` for responsibilities (#238), and `contact.*` for federation (#243). A check now fails when a call in the syscall map has no signature in `docs/reference/syscalls.md` or the page names a call the SDK lost; it found 13 undocumented calls on its first run (#286).
- Public Worker RPC contracts for installation directory, onboarding, entitlements, funded inference, mail, and adapters live under `packages/gsv/src/services/`, so managed operators implement stable contracts while standalone uses local defaults (#238).
- The WebSocket wire protocol has a generated validator, and a check fails when it is stale (#238); it was regenerated for protocol 4 (#280).
- Rust host protocol types are generated from the SDK types into `host/crates/gateway-client/src/protocol/generated.rs` with an explicit numeric-width table; `protocol:check` fails on drift (#286).
- Cross-Durable-Object peer schemas (`ProcessIdentity`, `PeerPrincipal`, `PeerGrant`, `ConnectedPeer`) are pinned to the SDK types with `satisfies`, replacing two hand copies that had drifted (#286).
- Validation happens at hostile boundaries (wire, service, webhook) and typed values are preserved past them instead of re-validated; the JSON-RPC and account, inference, and email service boundaries are typed (#238).
- The MCP (Model Context Protocol) client is now in-repo over `@modelcontextprotocol/sdk` 1.29.0, replacing the Agents SDK; storage rows and OAuth key layout are unchanged so authorized servers keep working. Restores no longer block Kernel startup, failed SSE (server-sent events) starts no longer wedge the client, stale sessions recover, list refreshes are fenced per list, and removing a server purges its OAuth records (#286).
- CodeMode is optional at runtime: the gateway runs without the Worker Loader binding and `codemode.exec` returns a clear error when it is absent, so one bundle serves free and paid Workers accounts (#221).
- Body streams are credit based: every stream starts with a 4 MiB window, receivers grant more with `WINDOW` frames, senders wait when out of credit, and stream ids keep parity per side; the SDK channel and the Rust client implement the same rules (#280).
- The SDK's remaining schemas moved to zod mini, and the gateway no longer depends on the OpenAI SDK directly; a small shared SSE parser feeds the custom and Codex providers (#280).
- Workers AI goes through the pi-ai Cloudflare AI Gateway binding transport instead of a handwritten adapter; pi-ai is pinned to 0.84.2 because later versions crash Workerd at module evaluation (#257).
- A model whose transport target is a machine sends its requests through that machine for every provider, not only custom ones; Workers AI, which goes through a gateway binding, refuses a machine transport with a clear error, and a provider stream that ends without a terminal stop reason is reported as a failure instead of an empty success (#224).
- Streaming tool calls from SGLang are accepted despite the `null` placeholder fields it emits, so a `Shell` call is no longer silently dropped and the process no longer ends as `generation.empty` (#268).
- A strict, versioned telemetry event contract with closed property allowlists is exported from `packages/gsv`; it excludes prompts, messages, paths, URLs, tool arguments, credentials, and contact identifiers (#263).
- Browser target: semantic page controls (`page snapshot` returns an accessibility outline with element ids for `click`, `type`, `scroll`, and `key`), `--help` discovery for `tabs`, `page`, and `network`, and lazily loaded tab resources (#233, #234).
- The native `gsv` shell disables the just-bash private-range DNS guard, because Workers has no `dns.lookup` and every public hostname failed its preflight (#231).

### Managed service

- Installation identity is the outer security boundary: managed hostnames resolve through the trusted installation directory before any Kernel state is allocated, and Kernel, Process, Conversation, R2, ripgit, adapter accounts, inference, and background work are all scoped by an immutable `installationId` (#238).
- Accounts owns installation lifecycle: onboarding, directory lookup, status, restriction, recovery, and reset. Only `active` installations admit work; a reset moves the handle to a fresh installation and retains the old one pending deletion (#238).
- Funded inference is installation scoped with reservation, settlement, usage accounting, budget enforcement, and streamed generation; credentials and policy stay in the managed service (#238).
- The gateway binds directly to the inference installation's Durable Object namespace, keeping the entrypoint as a rolling-deployment fallback, and the provider response travels through a forwarded RPC target instead of a second relay; staging showed first chunks in 2.1 to 3.6 seconds (#253, #256).
- Managed `gsv/default` routing is an ordered list of complete model routes, and a content-free operational event records each failed provider attempt, including those recovered by fallback (#275).
- "GSV Included" is the deployment-supplied base of the model stack on managed installs, so a personal provider key extends the built-in models rather than replacing them; the internal DeepSeek to GLM route stays hidden behind the single entry (#281).
- Telemetry events are emitted at Process, Kernel, adapter, and Conversation boundaries, stay disabled unless a deployment attaches a consumer, and switch off producer log persistence and traces when enabled; managed inference events carry bounded failure kind, stage, retryability, provider status, and workload (#263, #266).
- Managed Telegram in production authenticates by webhook secret and signed-in pairing, so the actor allowlist is optional; staging can still supply `TELEGRAM_ALLOWED_ACTOR_IDS` (#245). Managed activity and deliveries are generation fenced and rejected webhooks retry (#238).
- Managed Slack ships with example app manifests for standalone and managed deployments, pairing, and workspace targets scoped to the paired user's OAuth authority (#255).
- Deployment uses reusable Alchemy constructs published in this repository; standalone deploys through Alchemy without the private infrastructure, releases carry self-describing manifests with checksums and dynamic adapter artifacts, and the managed infrastructure repository keeps credentials and deploys against a pinned service contract (#238).
- Adapter secrets are constructed inside the active deployment runtime and validated against their configured patterns; managed Wrangler bindings exist for production and development (#244, #256).
- Managed email runs as inbound and outbound workers with queues, dead-letter handling, and installation isolation, and fails closed when unavailable; standalone deployments need no email resources (#238).

### Internal

- The unused package extensibility stack was removed end to end, a net 26,766 production lines (#221), and other unreferenced gateway code and the gateway's Alchemy dependency followed (#280).
- The Process Durable Object went from an 11,372-line class to a 160-line composition root with explicit owners for controller, run, history, resources, and tools; the store was split into repositories and the monolithic test file into scenario files, net minus 19 lines (#270). The earlier move replaced PartyServer and Agents inheritance with a composed raw Durable Object runtime (#238).
- The Kernel runtime and adapter handlers were split by owner, dispatcher entry paths unified, and internal process syscalls mapped (#280).
- A gateway integration harness boots the production Wrangler topology and exercises HTTP, WebSocket, service-binding, and storage boundaries against deterministic fixture workers; Kernel stores are tested with real SQLite, and superseded mocked unit tests were deleted (#232).
- Oxlint with anti-slop rules runs at a zero-warning ratchet; thousands of speculative type checks and compatibility branches were removed (#238).
- Two fixes landed directly on `main` without a pull request: empty tool call ids are handled during compaction (d00c0c3a) and Telegram approval updates are preserved (2dd35d00).
- The `src/process/do.*.test.ts` files are excluded by name from the unit configuration since the Process refactor, and `do.test.ts` globs them all in as one file, so CI runs them as a single test file; to run one on its own locally, lift the exclusion in a throwaway config (#270).
